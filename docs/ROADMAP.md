# Orange Quant Roadmap：横截面选股（A 股 LGB 主线）

> 创建于 2026-08-11。上一版路线图（RL 数据扩充 R1–R6）已完成，见 `docs/finished/ROADMAP-rl-data.md`；更早的 qlib 重构版见 `docs/finished/ROADMAP.md`。
> 核心论点：**横截面宽度是最便宜的真实样本扩充**——每天 N 只股票同场竞技，N 从 50 → 2000 是几十倍的独立信息增量（对比时序重采样只是同一根 K 线的影子）。本路线图把 A 股 LGB 选股迁到新架构后，沿"加宽截面 → 强化评估 → 损失/中性化研究"推进。

## 现状（2026-08-11）

- 新架构 LGB 流水线（`orange_quant.lgb.{dataset,train,backtest}`）市场无关，但**只有币安配置**（`binance-lgb-momtopk`：IC 0.034 / 净超额 +17.3% / IR 0.77，test 2026-02~06）
- A 股 LGB 停在 legacy qlib 版（git tag `legacy-pre-rl-refactor`）：csi300-lgb-momtopk IC 0.035（test 2017-2020）；-2026 版（test 2023-2026）组合层指标因 qlib dev 版 PortAnaRecord bug 不可信，仅 IC 可信
- `data/cn_raw/` 已有 **4826 只**股票日线 CSV（腾讯源，复权+单位换算已在 `data/tencent.py` 处理，至 2026-08）
- `universe.freeze_universe` 支持 A 股流动性池（按日均成交额 top-N，冻结无前视）
- RL 联合训练（R4）已证明 A 股横截面对策略泛化有正贡献

## 路线图（按性价比排序，可独立落地）

### C1. A 股 LGB 基线迁移到新架构（纯工程）

**动机**：一切 A/B 的前提。legacy qlib 版报告层有 bug、股票池写死 csi300 成分，新架构回测自算不受影响。

- [x] `config/cn-lgb-momtopk.yaml`：`market.type: cn`，top-300 流动性池（`liquidity_start/freeze_date` 参照 RL 的 A 股配置），train/valid/test ≈ 2018-2023 / 2024 / 2025-2026-08
- [x] 跑通 dataset → train → backtest 全链路；确认 A 股 CSV（列名/停牌日/涨跌停日）在共享日历对齐逻辑下无异常（发现并修复：停牌日持仓估值 NaN 传染 → ffill 按最后一笔收盘价估值，交易仍要求真实 bar）
- [x] backtest 基准换成指数或等权（`benchmark` 对 A 股取 SH000300，确认 cn_raw 里有指数 CSV，没有则用等权池）
- [x] 记录基线三件套：**IC / ICIR / TopK 净超额**，作为后续所有 A/B 的对照 —— **IC 0.0453 / ICIR 0.255 / 净超额 +23.8% 年化**（test 2025-01~2026-07，top-300 池，vs SH000300，IR 0.675，换手 24.6 次/年；PR #21）

### C2. 截面加宽 A/B（top-50 → 300 → 800 → 2000+）

**动机**：横截面样本 ×N 是本路线图的主菜；且小市值票上因子通常更有效（拥挤度低）。

- [x] 同一配置只改 `universe.top_n`，四档各跑一次，对比 IC / ICIR / 净超额 / 换手 —— `scripts/gen_cn_ab_configs.py` 生成四档（PR #23）；test 2025-2026：**top-50 IC 0.0001 / top-300 0.0453 / top-800 0.0494 / top-2000 0.0570**；ICIR 0.000→0.592 严格随宽度上升；净超额 top-50 −8.9% / top-300 +23.8% / top-800 +12.5% / top-2000 +46.1%；换手 16~25 次/年
- [x] 加流动性下限过滤（日均成交额绝对门槛），剔除不可交易小票，避免"纸面 alpha" —— `freeze_universe` 新增 `min_amount`（cn 基线 5000 万元，只切 2000 名以下，四档同规则）；2017 冻结窗过 200 日门槛的池仅 2656 只
- [x] 关注两个方向的张力：截面越宽 IC 通常越高，但 TopK 落在小票上的**容量与冲击成本**越差——净超额与 IC 结论可能背离，两个都要看 —— 背离已确认：top-800 IC 0.0494 > top-300 但净超额 12.5% < 23.8%（组合层路径噪声）；top-2000 TopK 落 0.5 亿成交额小票，真实资金需重估容量（当前 100 万账户无冲击）
- [x] 若 2000+ 档训练内存吃紧，dataset 层 npz 缓存分段加载 —— **不需要**：top-2000 feats 2.8GB，32GB 内存下 dataset/train/backtest 全链顺畅（C2.4 关闭）

### C3. 横截面评估报告（研究基建）

**动机**：宽截面 A/B 只看单个 IC 数字会误判，需要一套标准报告。

- [x] `lgb/backtest.py`（或独立 `lgb/report.py`）输出：per-day IC 序列 + 累计图、ICIR、分年度 IC、**decile 收益单调性**（预测分 10 档的实际收益阶梯）—— 已实现 `lgb/report.py`，`backtest` 主流程自动生成（PR #22）
- [x] **多空 spread**（top decile − bottom decile 日收益）：纯 alpha 度量，剥离市场 beta——A 股实盘难做空，仅作评估指标，不进交易 —— 含 t 统计量；C1 基线上 spread 日均 +0.00237（t=3.62）
- [x] 报告落 `outputs/<config>/report.md` + png，方便跨实验对比 —— `report.md` / `report_ic.png` / `report_deciles.png`；metrics.json 补 `icir`/`rank_icir`

### C4. 特征截面标准化 A/B（研究）

**动机**：当前 raw Alpha158 直接喂 LGB。树模型对单调变换不敏感，但特征的**跨日分布漂移**会让分裂点在不同市况下含义不同；per-date 截面 rank 让"排前 10%"跨时期同义。

- [x] dataset 层加可选 `features.cs_norm: rank|zscore|none`（per-date，对非 NaN 截面）—— 已实现（PR #24），默认 none 保持 legacy 原始 Alpha158 字节不变
- [x] A/B vs C1 基线；预期增益温和（Alpha158 多为比率型特征），负面则记录后关闭 —— **zscore 温和正向，保留为可选**：IC 0.0453→0.0513、ICIR 0.255→0.295、decile spread t 3.62→5.04、净超额 +23.8%→+24.9%；**rank 记录后不启用**（ICIR 0.274 微升但净超额掉到 +13.3%，组合层噪声，与 C2 top-800 同款背离）；默认仍 none（一次只改一个变量）

### C5. 排序损失 LambdaRank（研究）

**动机**：TopK 只消费排序，MSE 优化的是回归误差——目标错配。LightGBM 原生支持 lambdarank。

- [x] label 转每日相对收益分档（如 5 档 quantile 整数 relevance），`group` = 交易日（`date_idx` 已有，dataset 层现成）—— 已实现（PR #25）
- [x] `lgb.loss: lambdarank` 配置化，对比 MSE 基线的 IC / 净超额 —— **结果显著为负**：valid IC 0.0096 vs 0.0257、test IC 0.0136 vs 0.0453、RankIC −0.0255（转负）、净超额 −3.4% vs +23.8%、decile t 0.97；已排查非机制 bug（预测方差正常但逐日相关 ≈0/负）——exp gain + NDCG@10 在此池/区间学不到正确排序；基建保留（loss 分派可配置）
- [x] 备注：lambdarank 对 top 的加权天然契合 TopK 策略，值得认真做；但 A 股单日 group 大（300~2000），训练耗时预计上升 —— 训练耗时实测**不高**（5 seeds ~3 分钟，早停 130-250 轮）；后续候选调参（如线性 label_gain、更多分档、NDCG@50、宽池 top-2000 上重试）留待再研究，本路线图内不展开

### C6. 行业中性化（需新数据）

**动机**：Alpha158 的动量/波动率因子隐含行业贝塔，行业内相对强弱才是更纯的个股 alpha；组合层也避免 TopK 挤在单一行业。

- [x] 行业分类数据：腾讯/akshare 申万一级行业快照，落 `data/cn_industry.csv`（当前快照近似历史，survivorship caveat 与 universe 的 membership 同款，文档记录）—— `scripts/fetch_cn_industry.py`（PR #26）：akshare 申万官网接口（东财/新浪/历史分类 SSL 均被限），5202 只 × 31 行业；top-300 池覆盖 291/300（未覆盖为退市/吸收合并）
- [x] label 行业内 z-score（替代全截面 z-score）A/B —— **排序度量大幅提升但净超额崩掉**：valid IC 0.0257→0.0439、RankICIR 0.101→0.381，但净超额 +23.8%→**−9.4%**、decile t 3.62→1.62——全截面模型隐含行业动量轮动（基线 TopK 有色 15.6%/计算机 9.4%），2025-26 该部分贡献主要收益；行业内 alpha 更稳但量级小；且 label 中性化不动特征层原始水平（indneutral TopK 漂到防御银行 22.8%）。**记录，不采用**；彻底中性化需特征层处理（超出本路线图）
- [x] 报告层加组合行业暴露统计（TopK 持仓的行业集中度）—— report.md 新增行业暴露段（日均权重/top-3/HHI），backtest 输出 positions.csv；无行业映射（crypto）时自动跳过

### C7. 反哺 crypto LGB（可选，搭车）

- [x] C4/C5 中验证为正向的改动应用到 `binance-lgb-momtopk`（48 币池截面小是其短板，排序损失可能同样受益）—— C4/C5 唯一正向改动是 `cs_norm: zscore`，已应用到 binance 变体 A/B：**纯 alpha 度量全面退步**（test IC 0.0433→0.0241、ICIR 0.188→0.092、decile t 0.71→0.13 无显著性），仅组合路径净超额 +11.2%→+22.0%——再次印证净超额与 IC 背离，且 alpha 层无证据支撑，**判定不采用**（lambdarank 为负未反哺；crypto 基线维持 raw Alpha158）

## 研究记录：24 钟点实验（2026-08-11/12，用户需求）

把一天 24 小时构成 24 个数据集（`data.hour_of_day`，各钟点锚定的日频序列，
label = 隔日同钟点收益），各自独立 dataset→train→backtest（PR #27 基建，
#28 稳定性分析）：

- **机制成立**：24 个钟点全部跑通、全部正 IC（0.013~0.060），无死钟点；
- **钟点差异是噪声**：子窗口排名相关 ≈ 0（sw1-vs-sw2 +0.03），全窗"最佳小时"
  12:00 +175% 由一段 60 天暴涨撑起（去掉后 0/24 个钟点 bootstrap CI 排除 0）；
- **可辩护结论**：12/24 钟点三子窗口全正——"每个钟点都弱跑赢 BTC"成立，
  "某钟点更强"不成立；
- **年化超额误差**：6 个月 × 48 币，SE ≈ ±70%（正态近似）/ ±25-60%（block
  bootstrap，日超额均值回归）；t ≈ 0.3，任何 crypto 6 个月超额数字都是噪声量级；
- 复现：`scripts/gen_binance_hour_ab.py` + 24 条 dataset/train/backtest；
  分析：`scripts/hour_of_day_stability.py`。

## 研究记录：24 钟点 ensemble（2026-08-12，用户需求）

既然"哪个钟点更强"不可判定，正确落地是不择优、**24 个钟点一起给分、按日聚合后决定买卖**。分数层 ensemble（`orange_quant/lgb/ensemble.py::HourEnsemble`）：每个钟点模型在自己的钟点锚定序列上出分 → per-date 截面 z-score → 24 个钟点取均值（全窗 24/24 都在场时与求和排序等价）。基建：`scripts/gen_binance_hour_ensemble.py` 生成 config + 无训练 model.pkl（`binance-lgb-momtopk-hour-ensemble`，参考数据集=h00 缓存，执行价取午夜锚定日线）。

- **对齐事实**：24 钟点日历在 180 个决策日内逐日一致（差异只在 2019 warmup 与 h00 独有的 2026-08-01 标记日），成分 48 币一致；跨钟点预测相关均值仅 **0.58**（min −0.46）→ 降噪空间大；
- **alpha 层（test 2026-02~07，180 天）**：IC 0.0473（≈ h00 0.0488，弱于 h23 0.0603）、**RankIC 0.0724 为 25 配置第一**（h00 0.0522，+39%）、RankICIR 0.359 第一、ICIR 0.191（低于 h00 0.224，但 h00 由 sw3 单段 0.430 撑起，ensemble 三窗 0.287/0.218/0.068 均衡）；**IC 三子窗全正**（+0.069/+0.055/+0.018），sw2 是 25 配置的 IC winner（多数钟点 sw2 弱/负，h00 −0.017）；
- **组合层**：超额三窗全正（+43%/+29%/+123%），年化 +60.2%，bootstrap CI [−18.6%, +116%]；全窗最佳钟点 h12（+218.9%）仅 1/3 子窗保持最佳——择优不可靠再次确认；
- **短板（照实）**：decile spread t=0.25（h00 2.46）——共识把极端尾部磨钝：ensemble 底部十分位是"共识烂票"（24 钟点平均 z −1.3σ，但单钟点原始分 ≈0），收益空间里分不开多空腿；rank-mean 变体 t 修到 0.93 但 IC 掉到 0.031，**不采用变体**；
- **判级：采用**为 24 钟点实验的正确落地（"普遍弱正"升级为结构可用：IC 3/3 + RankIC 每窗 top）；对 long-only topk 策略短腿不交易，spread 弱影响有限；组合层超额与 h00 在噪声内（CI 大量重叠），不作"更好"claim。

## 研究记录：24 钟点池化 vs 集成（2026-08-19，用户需求）

补上 24 钟点研究缺失的第三条路：把 24 个钟点**堆成一个训练集**（110 万行，
"数据增强"读法），对照已有的"每锚点一模型"和"24 模型分数集成"。基建：
`orange_quant/lgb/pooled.py`（小时特征 + 共享 booster 的逐锚点代理）、
`scripts/gen_binance_hour_pooled.py`（训练，embargo=2 天purge 标签跨段泄漏）、
`scripts/run_hour_designs.py`（4 设计 × 24 锚点统一回测）、
`scripts/analyze_hour_designs.py`（分布 + 配对 + block bootstrap + 子窗口）。
`HourEnsemble` 增加 `ref_hour`，使集成也能在任意锚点上执行、拿到同口径分布。

test 2026-02~08（179 天，48 币），每个设计 24 个锚点各回测一次：

| 设计 | Sharpe 均值 | Sharpe 标准差 | 最差 | 最好 | IR 均值 | IC | RankIC |
|---|---|---|---|---|---|---|---|
| 每锚点一模型 | +0.450 | 1.022 | −0.668 | +3.429 | 0.921 | 0.0334 | 0.0487 |
| 24 模型集成 | +0.442 | **0.133** | +0.218 | +0.848 | 1.095 | **0.0445** | **0.0637** |
| **池化单模型** | **+1.234** | 0.778 | −0.263 | +3.915 | 1.561 | 0.0429 | 0.0548 |
| 池化 + 小时特征 | +1.307 | 0.574 | +0.002 | +2.695 | **1.626** | 0.0400 | 0.0551 |

- **锚点运气 >> 设计差异**：单锚点设计的 Sharpe 极差 4.10（同一策略、同一
  179 天，只差日线在几点收），设计间均值最大差仅 0.87 → **4.8×**。任何单锚点
  报出的 Sharpe（如既有记录里 h12 的 3.43）都是运气读数。
- **池化赢，且过门槛**：逐锚点配对 ΔSharpe +0.784（24 锚点 19 胜），block
  bootstrap（10 天块，锚点平均超额序列）Δ = +0.711，95%CI [+0.136, +1.352]，
  P(Δ≤0)=0.005；**3/3 子窗口池化都赢单锚点**（+0.610/+0.990/+4.140 vs
  +0.281/+0.706/+2.987）。IC 也从 0.0334 升到 0.0429。
- **集成不提高均值，只砍方差**：ΔSharpe −0.008（CI [−0.919, +0.852]，不可区分），
  但 Sharpe 标准差 1.022 → 0.133（**−87%**）、24/24 锚点为正。典型 bagging 特征：
  成员相关 0.58 太高，方差削减换不来均值提升。其 IC/RankIC 仍是四者最高。
- **钟点本身无信息（决定性）**：池化 + 小时特征（sin/cos/raw hour）训练后，
  小时特征在 5 个 seed 共 20916 次分裂中只被选中 **2 次**，增益占比 **0.004%**
  ——LightGBM 认为钟点不携带信号。这从机制上解释了为什么"每锚点一模型"没有
  结构优势：它为了捕捉一个不存在的异质性，把样本切成了 1/24。
- **噪声地板（本次最有用的副产品）**：pooled-hf 与 pooled 信息上等价（增益
  0.004%），差别仅来自 `feature_fraction` 采样路径（161 vs 158 列）——但逐锚点
  ΔSharpe 标准差 **0.840**、最大 2.505。**单锚点上 |ΔSharpe| < 1.7 的对比一律
  不可读**；只有 24 锚点均值（噪声对仅差 +0.073）才是可读量级。
- **判级：采用池化**为 24 钟点数据的默认训练方式（均值 + IR + 子窗口三重占优，
  机制解释自洽）。小时特征不采用（零增益，纯增加噪声面）。集成保留为**低方差
  变体**：若目标是"不管在哪个钟点部署都稳"，集成的 σ=0.133 无可替代；若目标是
  收益，池化更优。**两者可叠加**（池化模型 × 24 锚点分数平均）尚未测，是下一步。
- 复现：`gen_binance_hour_pooled.py --mode pooled{,-hf}` → `run_hour_designs.py`
  → `analyze_hour_designs.py`；产物 `outputs/hour-designs/`。

### 追加：池化 × 集成叠加（方案 4，同日）

上条留的「下一步」已跑。用**一个池化模型**给 24 个锚点特征序列各出一次分 →
每日截面 z-score → 平均。即"一个模型、24 个视角"，池化供均值、混合供方差。

| 设计 | Sharpe 均值 | 标准差 | 最差 | IR | IC | RankIC |
|---|---|---|---|---|---|---|
| 每锚点一模型 | +0.450 | 1.022 | −0.668 | 0.921 | 0.0334 | 0.0487 |
| 24 模型集成 | +0.442 | 0.133 | +0.218 | 1.095 | 0.0445 | 0.0637 |
| 池化单模型 | +1.234 | 0.778 | −0.263 | 1.561 | 0.0429 | 0.0548 |
| 方案 4 池化×24视角·日历日 | +2.644 | 0.398⚠ | +1.534 | 2.145 | 0.0461 | 0.0621 |
| 方案 4 噪声地板参照 | +2.497 | 0.402⚠ | +1.591 | 2.232 | 0.0430 | 0.0619 |
| **方案 4（池化×24视角·滚动24h）** | +2.237 | 0.821 | +1.042 | 1.997 | **0.0495** | 0.0610 |

- **叠加成立**：方案 4 同时拿到池化的均值（+2.644 vs 池化 +1.234）和更低的
  锚点间离散，24/24 锚点为正、最差锚点 +1.534，子窗口三段全正
  （+0.658/+1.962/+4.323）。逐锚点配对 ΔSharpe **+2.194**（22/24 胜）。
- **⚠ σ 口径不一致（后补，修正上表读法）**：按日历日对齐的混合分数**与目标锚点
  无关**——`build_ens_blend` 返回一个 date→row 字典，24 个锚点共用同一份（实测
  h08/h16/h23 对 h00 的分数差 = 0.000000）。所以标 ⚠ 的两行（以及"24 模型集成"
  的 σ 0.133）的 24 次回测**只差执行价、不差信号**，其 σ 只测了执行价差异，
  系统性偏小，**不能与 single / pooled / 滚动24h 的 σ 直接比**——后者确实产出
  24 个不同信号（滚动24h 实测差 0.51/1.51/1.38）。
  推论：先前"集成把 Sharpe 标准差砍掉 87%"的说法**夸大了 bagging 的功劳**，
  那里只有一个估计被量了 24 遍；而滚动24h 的 σ=0.821 看着更大，部分正因为它
  诚实地产出了 24 个不同信号。判级不变（滚动24h 在 topk 扫描、IC、可部署性
  上都赢），但 σ 一列不是同一口径。`analyze_hour_designs.py` 已在表下自动打印
  该警告（`SHARED_SIGNAL`）。
- **查过新鲜度混淆（关键）**：binance K 线时间戳是**开盘时间**，锚点 h 的
  `t h:00` 线收在 `t (h+1):00`，所以按日历日对齐时混合信号的最晚截止是
  `t+1 00:00`（来自 h23）——严格早于任何锚点的执行价 `t+1 (h+1):00`，**无前视**；
  但它比锚点自己的截止 `t (h+1):00` 最多新 23 小时，会抬高混合类设计。
  因此加了 `scores_ens_causal`：h′≤h 取当日、h′>h 取前一日，每个视角都截止于
  目标锚点自己的决策时刻之前，即**真正可交易的滚动 24h 混合**。
  自证：h23 无更新视角，滚动24h 与按日历日对齐逐位相同（2.786 = 2.786）。
- **命名约定**：措辞一律用**滚动24h**（设计是什么）/ **按日历日**（被替代的对照），
  代码 ID 保留 `-causal` 后缀（`pooled-ens-causal`/`ens-causal`/`scores_ens_causal`/
  `test_causal_alignment.py`，产物路径已固化）。"因果"是精确的信号处理术语，但
  **只在写明参考点后才成立**：这里指相对**决策时刻**因果；相对**执行时刻**两版都
  因果、都无前视，按日历日那版只是比自己的设计意图更新鲜。裸用"非因果"易被误读成
  "有前视 bug"，故文档不用。
- **滚动24h 仍然赢**：均值 +2.237（新鲜度只占 2.644−2.237 ≈ 0.41），bootstrap
  Δ vs 单锚点 **+1.302，95%CI [+0.124, +2.656]**，P(Δ≤0)=0.010；子窗口三段全正；
  **IC 0.0495 是全部 8 个设计里最高**（单锚点 0.0334，ΔIC +0.0161，24 锚点赢 21 个）。
  IC 基于 180 天 × 48 币的日截面，比 Sharpe 稳定得多——这是效应为真的最强证据。
- **副发现**：同样的视角对齐用在原 24 模型集成上也有效（`ens-causal` 均值
  +0.678 vs 原 +0.442），但仍远低于池化系。**已采纳的 `hour-ensemble` 配置存在
  同一个新鲜度性质**（不是前视，但比成员新），复盘其历史数字时需知道这点。
- **判级：采用方案 4·滚动24h**为 24 钟点数据的最终形态（一个池化模型 + 滚动 24h
  视角平均）。它同时是最贴近"用滚动窗口取代日历切分"的落地形式。
- **照实说**：Sharpe 2.2~2.6、sw3 高达 4.3~5.6，说明后段一波行情贡献很大，
  bootstrap CI 宽到 [+0.37, +4.80]。**设计间相对排序三窗稳定，绝对水平不可外推**；
  换手从 14.7 升到 16.1，成本敏感度需在实盘参数下另测。

复现：`run_hour_designs.py`（8 设计 × 24 锚点 = 192 次回测）→ `analyze_hour_designs.py`。

### 追加：topk 扫描判真伪（同日，**修订上面的判级**）

上面留了个未解释的张力：视角平均带来的 ΔIC 只有 +0.003~+0.011，ΔSharpe 却有
+1.0~+1.4，完全不成比例；且 `ens` 拿到最大 ΔIC（+0.011）却零 ΔSharpe。若增益
是真的（混合专门清理了排序**顶部**，恰好是 topk 交易的部分、也恰好是全名 IC
测不到的部分），则 Δ 应在窄组合最大、随宽度单调衰减、在 topk=40/48（几乎不做
选择）收敛到 0；若是运气，则应随宽度乱跳。5 个宽度 × 5 设计 × 24 锚点 = 600 次回测：

ΔSharpe vs 池化单模型（24 锚点均值）：

- **滚动24h 通过**：**每个宽度都为正，且严格单调衰减**（+1.661 → +0.414），

- **但 CI 都含 0**：滚动24h 逐宽度 bootstrap Δ 分别为 +0.46/+0.53/+0.59/+0.51/+0.32，

### 回归测试：`scripts/test_causal_alignment.py`

滚动24h 视角对齐是这套东西里**唯一一处"错了也不会报错、只会让回测变好看"**的地方：
`hp <= hour` 写成 `hp < hour`、或干脆去掉回退，都不抛异常、不产生 NaN、任何指标
上都看不出异常，只是悄悄把新鲜度还回去（而 topk 扫描已证明按日历日对齐的版本
优势是宽度巧合）。因此固化成回归测试，四层检查：

- **A 时刻算术**（无需数据）：对全部 24 个目标锚点，24 个截止时刻互异且逐小时
  连续、最新者恰等于目标自身、窗口=回溯 24h、且严格早于执行时刻；
- **B 回退计数**：回退到前一日的视角数恰为 `23 − h`；
- **C 生产 vs 独立复算**：`scores_ens_causal` 与按文档契约另写的 oracle 逐元素相等
  （`max|Δ| = 0.0`，24/24 锚点）；
- **D h23 恒等式**：h23 无更新视角 → 滚动24h 与按日历日对齐**必须逐位相同**；
  h00（回退 23 个视角）**必须不同**（实测 max|Δ| = 4.563）。

**已做变异验证**（测试本身可信）：注入 `hp <= hour → hp < hour` → `FAIL: 有效元素
数不同`；注入完全去掉回退 → `FAIL: 最大差 4.563e+00 > 1e-12`。两次都被抓住，
源文件已逐字节还原。

用法：`../.venv/bin/python scripts/test_causal_alignment.py`（h00/h08/h23，快）
或 `--all`（24 个锚点）；失败退出码非 0。**改动 `scores_ens_causal` 或任何视角
对齐逻辑后必须先跑它。**

`--explain [--explain-target H]` 顺带打印视角对齐表（纯时刻算术，不加载数据）：
24 行「视角 / 取哪天 / 滚动24h截止 / 按日历日截止」，标出日界、最旧、最新=目标自身，
并给出窗口区间与两版距执行的小时数。**表是从时刻算术推出来的，不是手写常量**，
所以不会与实现脱节。边界值可自查：`--explain-target 23` 无日界线、按日历日对齐晚 0h
（即 h23 恒等式）；`--explain-target 0` 回退 23 个视角、按日历日对齐晚 23h 且其最新
信息距执行只剩 1h（这就是新鲜度混淆的上界）。

## 稳定性复检（2026-08-12，`scripts/backtest_stability.py`）

对 C2/C4/C6 的 A/B 补做子窗口滚动验证（test 拆 3 段 × IC/ICIR/RankIC/超额 + block-bootstrap CI），结论分级：

- **C2 top-2000**：IC 三窗全正且 ICIR 高（0.63/0.75/0.44）——**宽截面 alpha 边缘稳健**；但超额优势由 sw1（+124%）撑起，sw2/sw3 被 top-300 反超，全窗 CI [+1.5%, +66%]。**top-300 最一致**：超额三窗全正（+19.8/+35.7/+8.6%），CI [−4.5%, +46%]。top-50 三窗 IC 两段为负，确认死亡。
- **C4 zscore**：IC 三窗全部 ≥ 基线（0.065/0.041/0.048 vs 0.064/0.031/0.041），超额三窗全正且 2/3 窗赢——**"温和正向"升级为"alpha 层一致正向"**；csrank 的 sw3 超额 −13.2%，不采用维持。建议后续 A/B 默认在 zscore 基线上做。
- **C6 行业内中性**：RankIC 三窗全部优于基线（排序提升稳定），但超额 2/3 窗为负（+14.9/−17.2/−18.5%）且基线 3/3 窗胜——**净超额崩不是单窗巧合，不采用确认**。
