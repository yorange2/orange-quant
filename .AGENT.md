# Orange Quant Agent Guide

## Project Overview

Orange Quant is an AI-powered quantitative trading framework built on Microsoft qlib. It supports:
- **Backtesting**: A-share (CSI300) and Binance spot
- **Auto-trading**: Local and Dockerized server with Binance mainnet execution
- **ML models**: LightGBM + 15+ PyTorch models (LSTM, GRU, Transformer, etc.)
- **Data pipeline**: Binance API, qlib data format

## Key Architecture

Shared core + thin per-exchange adapters. All trading/experiment logic lives once
in `orange_quant/`; each exchange package is an adapter (broker + `ExchangeSpec`)
that delegates to it, so a fix lands on every exchange at once.

```
orange_quant/                 # shared, exchange-agnostic core
├── spec.py                   # ExchangeSpec — the one knob per exchange
├── runner.py                 # StrategyRunner (configurable rotation/liquidity/blacklist)
├── server.py                 # run(spec, argv) — daily rebalance loop + CLI
├── experiment.py             # QuantExperiment + run_from_yaml + run_dl_from_yaml
├── model_predictor.py        # ModelPredictor(model_path, provider_uri)
├── blacklist.py              # reduce-only blacklist (path-parametrized)
├── trading/paper_broker.py   # shared PaperBroker (quote-ccy + ccxt factory)
└── data/pipeline.py          # download -> CSV -> qlib-binary machinery

biance_lgb_momtopk/  |  hyperliquid_lgb_momtopk/     # adapters
├── spec.py                   # BINANCE_SPEC / HYPERLIQUID_SPEC
├── server.py / train.py      # thin entrypoints -> orange_quant.*
├── trading/broker.py         # live broker (coin-based interface)
└── data/build.py             # exchange get_top_symbols/fetch_daily -> pipeline
```

Behaviour is preserved per exchange via the spec (no exchange branches in core):
- **Binance**: full daily rotation (`honor_config_rotation=False`), reduce-only
  blacklist on, no liquidity filter.
- **Hyperliquid**: partial rotation from the model YAML (`n_drop`/`hold_thresh`),
  liquidity filter on, no blacklist.

`workflow/experiment.py`, `trading/runner.py`, `trading/model_predictor.py`, and
`trading/blacklist.py` in each package are back-compat re-exports of the core.

Thin-layer philosophy: model, strategy, and data handling are delegated to qlib directly via YAML config.

## Commands

### Setup
```bash
source .venv/bin/activate
pip install git+https://github.com/microsoft/qlib.git
pip install lightgbm pandas numpy pyyaml ccxt python-dotenv
# macOS: brew install libomp
```

### Experiments
```bash
# A-share CSI300
python scripts/csi300/build_data.py
python -c "from biance_lgb_momtopk.workflow.experiment import run_from_yaml; run_from_yaml('config/csi300-lgb-momtopk.yaml')"

# Binance spot
python -m biance_lgb_momtopk.data.build --top 50
python -c "from biance_lgb_momtopk.workflow.experiment import run_from_yaml; run_from_yaml('config/binance-lgb-momtopk.yaml')"
```

### Auto Trading
```bash
# Local dry-run (recommended first)
python -m biance_lgb_momtopk.server --once --dry-run --model models/binance-lgb-momtopk.pkl

# Local live
python -m biance_lgb_momtopk.server --once --model models/binance-lgb-momtopk.pkl

# Docker
docker compose up -d
docker compose --profile dry-run up -d orange-quant-dry
```

## Data Locations

- `data/binance_raw/` — Binance daily CSV (gitignored)
- `data/qlib_data/binance/` — qlib binary for Binance (gitignored)
- `data/qlib_data/cn_data/` — A-share data (gitignored)

## Key Findings

1. **Costs matter**: Binance 0.1% taker fee eats ~50% of excess returns
2. **Cross-sectional features need enough instruments**: Alpha158 rank features need 20+ coins

## Environment

- Python: 3.9+ with venv in `.venv/`
- macOS: requires `brew install libomp` for LightGBM
- Docker: `docker compose up -d`
- API keys in `.env` (gitignored): `BINANCE_API_KEY`, `BIANCE_SECRET_KEY`
